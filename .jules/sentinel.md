## 2025-06-10 - Path Traversal Vulnerability in TypeScript Dependency Extractor
**Vulnerability:** In `crates/flow/src/incremental/extractors/typescript.rs`, manual path normalization for unresolved relative imports did not correctly handle `../` (ParentDir) path components when resolving paths outside the immediate source tree. This could lead to malicious imports traversing up to arbitrary directories, bypassing file boundaries because popping `ParentDir` blindly from empty components or root components leads to incorrect paths, often losing the "out-of-bounds" relative nature completely.
**Learning:** Manual traversal normalization must not simply ignore or silently pop `..` tokens if the traversal exceeds the base scope. When canonicalization fails (e.g., if a target file doesn't exist yet but an import points to it), it's important to track and preserve `ParentDir` references when at the top level to maintain accurate file path structures and prevent bypassing safety checks further up the execution flow.
**Prevention:** Always handle `std::path::Component::ParentDir` explicitly. When the component stack is empty or the last component is already `ParentDir`, we must push `ParentDir` rather than popping/ignoring. Additionally, we must prevent popping `RootDir` or `Prefix` to ensure paths do not unsafely leave restricted scopes.
