## 2025-05-23 - Prevent Path Traversal in Component Normalization
**Vulnerability:** Path traversal during module resolution (`crates/flow/src/incremental/extractors/typescript.rs`). When manually resolving paths with `std::path::Component`, encountering `Component::ParentDir` was handled by unconditionally calling `components.pop()`. This allowed paths like `dir/../../passwd` to strip the relative path and silently traverse directories without being correctly preserved.
**Learning:** `std::path::Component::ParentDir` resolution isn't as simple as just popping the previous element. You cannot pop `Component::RootDir` or `Component::Prefix`, and if the previous element is already `ParentDir` (or the list is empty for a relative path), the new `ParentDir` must be explicitly pushed to preserve upward traversal securely.
**Prevention:** Always use a safe path normalization pattern when handling `ParentDir` manually that matches on the last pushed component type before determining whether to push or pop.
