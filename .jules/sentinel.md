## 2025-02-27 - Fix path normalization logic vulnerability in module resolution
**Vulnerability:** Path normalization logic using `.components()` manually popped `ParentDir` (`..`) tokens indiscriminately. This allowed for traversal via relative paths dropping important traversal bounds like `..` resulting in escaping intended path structures, and could also incorrectly pop `RootDir` or `Prefix`.
**Learning:** During manual path normalizations with `std::path::Component`, simply using `components.pop()` when encountering `Component::ParentDir` is flawed. If the stack is empty, it fails to record the `..`, changing the meaning of the relative path, which can cause security traversal vulnerabilities in logic trusting paths to remain correctly relative.
**Prevention:** To prevent path traversal vulnerabilities when manually normalizing paths, always explicitly check and block `Component::ParentDir` from popping `Component::RootDir` or `Component::Prefix`. Furthermore, if the component stack is empty or its last element is already a `Component::ParentDir`, append the `Component::ParentDir` instead of ignoring it to preserve the correct relative paths (e.g. `../../a`).
