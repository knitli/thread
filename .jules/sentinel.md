## 2026-06-04 - [Fix Path Traversal in Path Normalization]
**Vulnerability:** A path traversal vulnerability existed in `resolve_module_path` in `crates/flow/src/incremental/extractors/typescript.rs`. When manually resolving paths (if `canonicalize` fails), `std::path::Component::ParentDir` (`..`) simply popped the last component off the stack. This could allow an attacker to traverse above the root directory if a path like `/var/www/../../etc/passwd` was supplied, as it would pop the `RootDir` component, resulting in access to unintended files.
**Learning:** `std::path::Component::ParentDir` requires careful handling when building paths manually from components. Simply popping the last component is insufficient and dangerous because it can pop `RootDir` or `Prefix` components, or mishandle consecutive `ParentDir`s (e.g., `../../`).
**Prevention:** Explicitly check the last component before popping. Never pop `Component::RootDir` or `Component::Prefix`. If the list is empty or the last component is already `Component::ParentDir`, the new `Component::ParentDir` must be appended instead of ignored to correctly preserve relative paths.
